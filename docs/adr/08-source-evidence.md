# Freeze executable inputs before evidence

Status: implemented. See [artifact verification](../ARTIFACTS.md).

A summary can report success while omitting failed seeds, replacing checkpoints or inflating useful
work. The campaign freezes source, tests, configuration, locks, documentation and data-selection
manifests before running stages. An owned configuration copy supplies child commands. Raw author
identities are checked around stages; process receipts retain actual exits, clocks, logs and exact
output ownership. Source changes invalidate reuse of the prior acceptance bundle.

Trusting an acceptance JSON alone would be cheap but would not connect results to behavior.
Re-running a missing experiment inside verification would produce new evidence and conceal an
incomplete bundle. The chosen verifier reads retained outputs, independently reconstructs metrics
and physical arithmetic, and replays bounded source-selected probes through actual saved tensors.
It never repairs the bundle or retrains a model.

Hash inventories add I/O, especially for trajectories and many checkpoint generations. They prove
byte identity, while semantic checks must establish label boundaries, physical units and meaningful
counts. Complete feature coverage additionally binds every authored test function, capability,
command and raw artifact family. A structurally complete coverage map is not a scientific pass.
The full gate arithmetic remains mandatory.

Failed executions and disposable corruption controls remain retained. Rehashed semantic controls
must fail independent checks, not only checksums. Candidate publication stages a complete copy and
commits its final name only after validation; release packaging requires the full final verifier.
Diagnostic profiles keep their smaller scope and cannot become a full release. Documentation
validation is read-only during the frozen campaign; explicit diagram rendering occurs before the
freeze. This prevents a rendering tool from silently changing accepted inputs.
